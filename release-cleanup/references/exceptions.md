# 异常与恢复

每项独立执行；一项阻断不影响其余项。apply 返回非零表示还有阻断，不能把整批报告为已完成。STATE/plan.json 保存原 SHA 和文件哈希，journal.json 保存进度及发布确认，每项归档为 `<id>.tar.gz`，对应 `.backup.json` 校验来源与旧目标的完整内容。不手工改计划或进度来绕过检查。

- **同名文档/SQL 冲突**：来源不删，主目录不覆盖。归档中 `source/<相对路径>` 是来源，`destination/<相对路径>` 是首次备份时的主目录版本。只读这些文件比较；将双方有效内容合并到主目录，不改冻结的来源。主目录若与来源完全一致，直接重跑 apply；保留了双方内容的合并版用以下命令记录其哈希后再 apply：

```bash
python3 "$SKILL_DIR/scripts/cleanup.py" resolve --state "$STATE" --branch "$BRANCH" --file "ai_work/docs/商品/功能主题/需求.md"
```

resolve 只记录 agent 已审阅的合并结果，不能代替业务判断；SQL 语义不明确时询问用户。归档未成功前不执行合并写入。

- **中断**：重跑相同 apply。已校验归档不重复创建、相同文件不重复复制、已完成项不再删除。源码/主分支/文件清单发生变化时保留原 STATE，查明变更后用新 STATE 重新盘点，不刷新旧哈希掩盖变化。部分写入、备份损坏或来源提前消失时保留现场，依据已验证副本恢复，不能强行续删。
- **未合入、脏源码、未提交非文档文件、锁定/正在使用、submodule、符号链接、嵌套仓库或特殊文件**：保留该项。squash/rebase 不能通过祖先检查时不能只凭 diff 相同删除。代理工具管理或非同级 worktree 另走适用工具，不用 rm 绕过。
- **assume-unchanged/skip-worktree**：Git 可能隐藏实际修改，脚本会保留；不能为通过清理擅自清除用户索引标记。先确认隐藏修改的用途，再决定如何另行处理。
- **`git branch -d` 拒绝**：脚本只在它因 upstream/当前 HEAD 判断“未完全合并”时，重新核对发布主分支、功能 SHA 和占用后使用 `-D`。这使主目录留在旧 pre 也能收尾；其他删除错误保持阻断。

## 文档与本地产物

nros-mall-java 的 `ai_work/` 不提交。脚本自动复制以下缺失文件：三份正式主题文档 `ai_work/docs/<模块>/<主题>/{需求,实现方案,变更记录}.md`、主题 scripts/resources（排除 reports 和文档归档），以及 `db/*.sql`；相同文件跳过，冲突不覆盖。SQL 仍为未提交文件，不能表述为已执行或已上线。

其余 ignored、临时证据和旧布局文档只归档到主目录，不自动灌入源码或新建不合规则的主题。摘要中 archive_only 非零时，按需查看 plan 中这些路径：有长期价值的材料按项目规则整理，报告归档位置；不为收尾重写所有历史文档。普通未跟踪源码会阻断，不能仅凭已备份就删除未完成工作。

STATE 应与主目录在同一文件系统（默认放在主目录内即可）；文件通过原子 hard link 落到目标，跨文件系统时安全阻断。主目录已跟踪文件被用户删除时不会恢复。常规硬链接按独立内容备份；符号链接仍阻断。

仅排除带已跟踪 pom.xml 模块的默认 target 构建目录，含多层 Maven 模块；其他 ignored 文件完整备份。归档权限受限，不输出本地配置内容。脚本会互斥自身操作并在删除前重检，不能锁住编辑器或其他 Git 进程，运行时须停止修改候选目录。
